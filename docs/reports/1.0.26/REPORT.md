# 桃园助手 1.0.26 全链路时延追踪

## 目标

定位用户从屏幕出现 Hero 行动到悬浮窗显示结果的 3 秒以上体感耗时。此前生产日志只能确认服务端识别开始到决策完成约 1.36 秒，无法区分客户端采集节拍、串行上传等待、JPEG/Base64、网络和界面展示。

## 变更

- 每个上传帧生成不含账号信息的 trace id，使用 Android 单调时钟记录采集、Bitmap 成帧、容量 1 最新帧队列、被覆盖帧数、JPEG 压缩、请求体写入、HTTP、响应接收和悬浮窗下一帧展示。
- 串行上传期间被新帧替换时，最终上传帧继承最早待处理时间并累计覆盖帧数，用于量化“前一请求仍在执行”导致的隐藏等待。
- 读取服务端响应中的 bind、授权、识别、请求准备、决策和总耗时；完整记录打印为本机 `TRACE_COMPLETE`。
- 已完成记录随下一次正常截图请求回传，不新增遥测请求、不并发调用 ddbaby，容量 1 最新帧语义不变。
- 追踪数据缺失或无效时不改变上传、决策和悬浮窗业务结果。
